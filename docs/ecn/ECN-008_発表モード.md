# ECN-008: 発表モード (スライド表示 + 録音 + ページ紐付け)

- **ステータス**: 適用済 (PR #19、2026-07-20 マージ)
- **種別**: 機能追加
- **対象コミット**: 24コミット (先頭 `be510dd4` / 末尾 `bb58418d`)
- **規模**: 84ファイル (core/apps 46 / tests 9 / docs 4)
- **影響ファイル**: `core/storage/source_links_repo.py`,
  `core/storage/source_markers_repo.py`, `core/slides/`,
  `apps/api/routers/source_links.py`, `apps/web/src/lib/components/SlideView.svelte`,
  `apps/web/src/lib/stores/presentation.svelte.ts`

## コンテキスト

資料を見せながら話した内容を、後から「何ページ目の話か」で引けるようにしたい。
録音と資料が別々のソースとして並ぶだけでは、両者の対応が失われる。

## 対策

### 1. ソース間結合は汎用の親子リンク基盤 (ADR-001)

発表専用のカラムを足さず、`source_links` テーブルで**汎用の親子関係**を持つ。
自己リンク・重複・循環は登録時に拒否する。

**採用しなかった案**: `sources.parent_id` を足す方式 (発表以外の結合
—— 例えば「この録音はこの議事録の元データ」—— を後から足せない)。

手動リンク (`relation=manual`) はソース単位のみ。ページ紐付けは発表だけが持つ。

### 2. ページ遷移は録音タイムラインマーカー (ADR-002)

ページめくりを「録音セッションのタイムライン上のマーカー」として記録する。
`at_ms` は**サーバー側**で既存の mic/system 共有 epoch から算出し、
**クライアント時計に依存しない**。

確定時に `source_markers` へ永続化し、チャンク化で `chunks.page` に
ページ番号を割り当てる (録音ソースの `page` = 「親資料の何ページ目で話したか」)。

### 3. PPTX の見た目再現は PowerPoint COM (ADR-003)

取込時に一度だけ `<id>.slides.pdf` を併産する。**PowerPoint 未検出環境では
縮退**する: テキスト取込は従来どおり成功させ、「発表を開始」だけを無効化して
「PDFに書き出して取り込むと発表できます」と案内する。

## 結果

- 実機検証レポートあり (証拠は `E:\\00_Git\\.archive\\notebook-ollama-eval\\pixelrag-stage4\\presentation-mode\\` に退避、21枚)
- 引用から親資料の該当スライドを開ける。ページ別の発言逆引きも可能

## 教訓

- **「AをやってからBを確定する」処理は、Bの失敗でAを巻き戻してはいけない。**
  発表確定が失敗しても録音の停止と保存は完走させる。ユーザーにとって
  失うと痛いのは録音であって、紐付けは後から直せる
- **専用カラムより汎用の関連テーブル。** `source_links` にしたことで、
  発表以外の結合 (Stage 2 の図説明チャンクの相互リンク等) にも同じ考え方を
  使い回せた
- **時刻はサーバー側の既存タイムラインから算出する。** クライアント時計を
  信じると、時刻ずれや一時停止で紐付けが静かにずれる
- **外部アプリ依存 (PowerPoint COM) は「無い環境で機能が縮退する」形にする。**
  取込そのものを失敗させると、発表を使わないユーザーまで巻き込む
