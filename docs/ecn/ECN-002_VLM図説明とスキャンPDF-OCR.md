# ECN-002: VLM図説明・スキャンPDF OCR・生成時画像投入 (Stage 2)

- **ステータス**: 適用済 (PR #25、2026-07-25 マージ)
- **種別**: 機能追加 + 不具合修正
- **対象コミット**: `eb0f6e2c..40ab89e5` (18コミット)
- **規模**: 48ファイル、+1,868 / -46
- **影響ファイル**: `core/ingestion/figure_describer.py`, `core/ingestion/ocr_engine.py`,
  `core/ollama/messages.py`, `core/ollama/models_info.py`, `core/storage/migrations.py`,
  `apps/api/routers/` (describe-figures / アセット画像配信)

## コンテキスト

ECN-001 で図をクロップ画像として保存できるようになったが、**画像は検索に乗らない**
ため「図に描いてある内容」は依然として answer できなかった。また画像のみで構成された
スキャンPDFは、テキストが1文字も抽出できず取込自体が無意味だった。

## 対策

### 1. 図説明は独立チャンク方式 (ADR-008)

VLM が生成した図の説明文を `chunks.kind='figure_desc'` の**独立チャンク**として
索引に載せ、`chunk_assets.desc_chunk_id` で図アセットと相互リンクする。

**採用しなかった案**: 元チャンクの本文に追記する方式 (元の本文と生成文の区別が
つかなくなり、フラグOFF時に切り離せない)。

### 2. VLM/OCR は Ollama 一本 + エンジン抽象化 (ADR-009)

`OcrEngine` / `FigureDescriber` インターフェースで抽象化。将来の差し替え
(専用OCRエンジン等) に備えつつ、実装はOllama一本に絞った。

### 3. 生成時の図画像 late-binding 投入

vision 対応チャットモデルを選んでいるときだけ、図画像をプロンプトに載せる
(`83f14ff`)。非対応モデルでは静かに落とす。

## 問題の詳細 (修正した実バグ5件)

実機評価8シナリオ中7 PASS。**残り1つの追及から芋づる式に5件の実バグが出た**。

| コミット | 症状 | 原因 |
|---|---|---|
| `695388b` | モデル一覧が丸ごと 500 | `/api/models` が個別モデルの `show` 失敗を握らず全体を巻き込んでいた |
| `a0c8d70` | `vision_model` を変えても反映されない | `figure_describer`/`ocr_engine` が起動時の値を掴んだままだった → Lazy 化 |
| `a7cf317` | ベータOFFでも `PUT /settings/vision-model` が 200 | ベータゲートの掛け漏れ |
| `82a422a` | **OCR拒否応答が ready 扱いで索引を汚染** | LLM の「この画像は読めません」等の応答を本文として保存していた |
| `9c62a96` | OFF時も figure_desc が検索に出る / 閲覧のたび再OCR | kind フィルタ漏れ + 結果の未保存 |
| `353deef` | `put_ollama_settings` が `vision_model` を巻き戻す | 部分更新で他スロットを潰す退行 |

**最も重い1件は `82a422a`**。VLM は失敗を例外ではなく**もっともらしい日本語の文章**で
返す。「申し訳ありませんが、この画像からテキストを読み取ることはできません」が
そのまま本文として索引に載り、検索でヒットして回答の根拠になっていた。

## 結果

- 品質ガードを入れ、拒否応答パターンを検出して**明示的な失敗**に倒すようにした
- スキャンPDFの取込が成立するようになった
- 図の内容に関する質問が answer 可能になった

## 教訓

- **LLM を部品として使うとき、失敗はエラーではなく「それらしい出力」で返ってくる。**
  例外処理だけでは捕まらない。出力そのものの妥当性検査 (拒否応答・ハルシネーション
  検出) を、パイプラインの保存直前に必ず置くこと
- **設定値を掴むタイミングは実行時に寄せる。** 起動時に解決するとモデル切替が
  無反応になり、ユーザーからは「設定が効かない」というバグに見える
- 設定の部分更新APIは、**触っていないスロットを巻き戻していないか**を必ずテストする
  (`353deef` は同種の退行)
