# ECN-007: チャット音声入力 (プッシュトゥトーク + ハンズフリー)

- **ステータス**: 適用済 (PR #18、2026-07-20 マージ)
- **種別**: 機能追加
- **対象コミット**: 22コミット (先頭 `ac482af4` / 末尾 `8c9cf55a`)
- **規模**: 57ファイル (core/apps 26 / tests 2 / docs 5)
- **影響ファイル**: `apps/api/routers/stt.py`, `apps/web/src/lib/audio/`,
  `apps/web/src/lib/stores/voiceInput.svelte.ts`,
  `apps/web/src/lib/components/ChatInput.svelte`,

## コンテキスト

チャット入力をキーボードだけに縛ると、図や資料を見ながらの問いかけが打ちづらい。
一方で「常時マイクを開く」設計はプライバシー面でも実装面でも重い。

## 対策

### ステートレス STT + ブラウザ側 VAD (ADR-004)

サーバーは `POST /api/stt/transcribe` の**1回1完結**な変換だけを持つ。
発話区間の検出 (VAD)・録音・16kHz mono WAV へのエンコードは**すべてブラウザ側**。

- `a2b0...` `feat(web)`: 16kHz mono WAV エンコーダ
- `feat(web)`: ハンズフリー用 RMS ベース VAD
- `feat(api)`: `POST /api/stt/transcribe`

**採用しなかった案**: WebSocket でのストリーミング STT (サーバーに発話状態を
持たせる必要があり、切断・再接続の状態管理が増える)。

**2つのモード**:

| モード | 操作 |
|---|---|
| PTT (プッシュトゥトーク) | 設定したキーを**長押し**している間だけ録音 |
| ハンズフリー | VAD が発話区間を検出して自動で切り出す |

## 問題の詳細 — 難所はほぼ「入力の横取り」だった

22コミット中7件が、音声認識ではなく**キーボード/マイクの制御**の修正だった。

| コミット | 症状 | 原因 |
|---|---|---|
| `fix(web)` PTT repeat | Space 長押しでテキストに空白が連打入力される | keydown の `repeat` を消費していなかった |
| `fix(web)` 遅延解決キャプチャ | 許可ダイアログ中にオフにしてもマイクが開く | `getUserMedia` の解決が遅延し、オフ後に開始していた |
| `fix(web)` 最終区間の破棄 | ハンズフリーを手動オフすると**最後の発話が消える** | 停止時に進行中の区間を捨てていた |
| `fix(chat-voice-input)` Space奪取 | textarea で Space が入力できない | PTT キーのフックがテキスト入力中も効いていた |
| 同上 マイク誤起動 | 意図しないタイミングで録音が始まる | タップ/長押しの判別境界 |
| 同上 カラートークン | 録音中の色が他UIと不整合 | 実在しないトークン参照 |
| `fix(api)` sync ハンドラ化 | ffmpeg 変換が非同期ハンドラをブロック | sync ハンドラへ変更 |

**PTT キーの判別は Claude Code と同じ「タップ/長押し」方式**に途中で改訂した
(`docs(specs)` の3コミット目)。タップは通常の文字入力、長押しだけが録音。
これがないと、Space を PTT にした瞬間に文章が打てなくなる。

## 結果

- 実機検証は**5/5 PASS**(修正後の再検証を含む)
- IME 変換中のガード (`AC8-ime-composing-guard`) を含め、日本語入力と共存する

## 教訓

- **キーボードショートカットを既存の入力欄に重ねる機能は、「その欄で普通に
  打てること」を先に壊す。** 機能そのものより、既存操作を壊さないための分岐
  (IME 変換中・textarea フォーカス中・repeat イベント) の方が実装量が多かった
- **マイク/カメラの許可は非同期に解決する。** 「開始要求 → ユーザーが許可 →
  ストリーム取得」の間にユーザーが停止操作をしうる。**解決後に「まだ有効か」を
  再確認する**経路が要る
- **停止操作は「進行中のものをどうするか」まで決める。** 「止める」を素直に
  実装すると最後の入力が消える。ユーザーから見れば「言ったのに入らなかった」
  というデータ欠落に見える
