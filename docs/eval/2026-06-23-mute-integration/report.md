## 1. 経緯: スモークが暴いた HIGH バグ → 設計変更

初回の実音声 E2E(システム音にミュート中「秘密のパイナップル」を発話)で **ミュート中発話がチャンクに漏洩**し、さらに **非ミュートの後続発話 C が誤除外** された。

並列の敵対的監査(Workflow / 15 エージェント)で確定した HIGH 原因と、E2E で判明したより深い原因:

- **HIGH(監査)**: `wav_start_offset_ms` を mic/system で 1 個共有していたが、各 WAV はチャンネル自身の最初のフレームから始まる(system ループバックは無音時フレームを落とすため mic と原点が秒オーダーでずれる)。→ per-channel offset 化を実装(Fix 1)。
- **より深い原因(E2E で実証)**: `recorder.py` はループバックのアイドル時フレームを書かない(`get_read_available() < 1024` で `continue`)。実測 **mic.m4a=94.5s / system.m4a=32.8s**(同一録音)。system WAV は「音があった区間だけ」を詰めた圧縮タイムラインで、壁時計のミュート区間を **定数オフセットでは写像不能(非線形)**。タイムスタンプ方式は loopback で原理的に破綻する。

→ ユーザー合意のもと **方式A(録音側で無音書き込み)** へ変更:ミュート中チャンネルの WAV に実音声でなく無音を書く。STT が無音から何も生成しない(VAD 除去)ため、変換・推論・埋め込み・音声認識すべてからミュート区間が確実に除外される。タイムスタンプ計算は不要になり、`mute_intervals.json` / オフライン除外フィルタ(旧 ②-BE2)/ wav_t0 / `mute_filter.py` は撤去。`MuteState` はチャンネル別の真偽値ホルダに簡素化。
