# 設計仕様: 発表モード (Presentation Mode) — Notebook Ollama

- 日付: 2026-07-06
- ステータス: 承認済み(ブレインストーミング完了)
- 対象: `apps/web` 発表ビュー/ソース一覧 + `apps/api` マーカー・リンク・スライド配信 + `core` 取込・リンク・ページ割当
- HTML併記版: `./2026-07-06-presentation-mode-design.html`(モックアップ入り)

## 1. 目的

スライド資料(PDF/PPTX)を見た目のまま表示しながら発表を録音し、発言をページ単位で資料に
紐付けてナレッジを強化する。中央のチャット領域をスライド表示に置き換え、右サイドバーに
話者名付きのライブ字幕を表示してライブ感を提供する。利用シーンは実際の発表・会議が主
(マイク+システム音声+話者分離をフル活用)。

あわせて、ソース同士を親子リンクできる汎用基盤を導入する。発表録音は発表資料の子として
自動リンクされ、任意ソースの手動リンクも可能にする(同一ノートブック内でソースがバラバラに
並ぶだけだった状態からの脱却)。

## 2. スコープ

### やること
- 発表モード: スライド表示(pdf.js)+録音+ライブ字幕+ページ遷移マーカー記録
- ソース親子リンク汎用基盤(`source_links`): 発表の自動リンク+手動リンクの両方
- 録音セッションへの汎用タイムラインマーカー機構の追加(案C)
- PPTX取込時のPowerPoint COMによるPDF併産(見た目忠実表示のため)
- 録音チャンクへの発表ページ番号割当(`chunks.page` 流用)
- 引用・閲覧でのリンク活用(親リンク表記、該当スライド表示導線、ページ別発言の逆引き)

### やらないこと(v1 非ゴール)
- PowerPointアニメーション・段階表示の再現(PDF化の時点で失われる)
- レーザーポインタ・描画注釈・発表タイマー等のプレゼンター補助ツール
- 発表モード中のRAGチャット並用(録音中と同様にチャットは非表示)
- スライドサムネイル一覧からのページジャンプ(v1はページ番号入力のみ)
- リンクを使った検索スコアリングの変更(v1はリンクを表示・ナビゲーション強化にのみ使用)
- LibreOfficeによるPPTX変換フォールバック(v1はPowerPoint COMのみ、無い環境は手動PDF化ガイド)
- 発表のライブ配信・外部共有機能

## 3. 主要な意思決定(確定事項)

| # | 論点 | 決定 | 理由 |
|---|---|---|---|
| 1 | 利用シーン | 実際の発表・会議が主 | システム音声+話者分離を最初からフル活用 |
| 2 | 対応形式 | v1からPDF+PPTX両対応 | ユーザー要件。PPTXは変換層で見た目再現 |
| 3 | PPTX変換 | PowerPoint COM(取込時に一度だけPDF併産) | 本家レンダリングで見た目が崩れない。無い環境はPDF化ガイドへグレースフルデグレード |
| 4 | ページ遷移の記録 | 録音セッションに汎用タイムラインマーカー機構(案C) | 録音側は「ページ」の意味を知らず結合最小。将来の別種マーカーにも流用可 |
| 5 | ナレッジ統合 | ソース親子リンク汎用基盤(手動+発表自動の両方をv1で) | ユーザー要件。発表は「資料=親、録音=子」の第一のユースケース |
| 6 | ライブ字幕位置 | 右サイドバー(ビューア領域)に話者名+時刻付き履歴 | 発言履歴を遡れる。既存LiveCaptionViewの資産を活用 |
| 7 | 録音コントロール | 既存録音機能と同じ左欄(RecordingControls)を流用 | UIを新設しない。発表用の追加は「発表を終了」の文言程度 |
| 8 | 操作ヒント | UIに常時表示しない | 画面をシンプルに保つ(ホイール等の挙動は実装仕様として定義) |
| 9 | 検索への反映 | v1はスコアリング変更なし、表示・ナビ強化のみ | YAGNI。録音チャンクは従来どおり自然にRAGヒットする |

## 4. データモデル

### 新規テーブル

**`source_links` — ソース親子リンク(汎用基盤)**

| カラム | 内容 |
|---|---|
| `id` | リンクID |
| `notebook_id` | 所属ノートブック |
| `parent_source_id` / `child_source_id` | リンクの親と子(`sources.id` 参照) |
| `relation` | `presentation`(発表モード自動)/ `manual`(手動)。将来種別追加可 |
| `meta` (JSON) | 付帯情報(発表リンクなら発表日時など) |
| `created_at` | 作成日時 |

制約: 自己リンク・重複・循環参照は登録時に拒否。

**`source_markers` — 録音タイムラインの汎用マーカー(案C)**

| カラム | 内容 |
|---|---|
| `id` | マーカーID |
| `source_id` | 録音ソースID |
| `kind` / `value` | `page` / ページ番号(将来 `important` 等も追加可) |
| `at_ms` | 録音タイムライン上の時刻 |

発表中はセッションがメモリで保持し、録音確定時に永続化する。

### 既存の再利用
- **ページ割当**: 録音のチャンク化時に page マーカーと時刻を突合し、既存の `chunks.page` に
  ページ番号を書く。録音ソースのチャンクにおける `page` の意味は「親発表資料の何ページ目で
  話したか」(この意味はコードコメントとSourceViewerのラベルで明示する)
- **スライド原本**: PDF原本は `sources_dir/<id>.pdf` に保存済み。PPTXは取込時にCOMで
  `<id>.slides.pdf` を併産。配信APIを1本追加し、フロントはpdf.jsで描画
- **録音・字幕・話者分離・ソース化**: 既存パイプラインを無改造で利用(マーカー受付APIのみ追加)

## 5. コンポーネント

| コンポーネント | 責務 |
|---|---|
| `source_links` テーブル(新規) | ソース親子リンクの汎用基盤 |
| `source_markers` テーブル(新規) | 録音タイムラインの汎用マーカー |
| PPTX→PDF変換(PowerPoint COM) | 取込時に `<id>.slides.pdf` を併産。PowerPoint未検出時はPPTX発表不可+PDF化ヒント |
| スライド配信API + pdf.jsビューア | 保存済みPDFを配信しページ単位描画。ページ送り◀▶とページ番号表示 |
| 発表モードUI(中央パネル) | 録音中のLiveCaptionView置換と同じパターンでチャット領域をスライド表示に置換。ページ送りのたびにマーカー記録 |
| ライブ字幕サイドバー(右パネル) | 既存LiveCaptionViewを右サイドバー用に再構成。話者名+時刻付き履歴、遡り可 |
| 録音セッション拡張(マーカー受付API) | 汎用マーカー記録APIのみ追加。録音側は「ページ」の意味を知らない |
| 自動リンク+ページ割当処理 | ソース化完了時に `source_links`(relation=presentation) 自動作成+`chunks.page` 書込 |
| 手動リンクUI(ソース一覧) | 「親ソースを設定…/リンク解除」操作と親子ツリー表示(見た目は既存カードのまま、インデントのみ) |

### データフロー

```
発表開始 → 録音+字幕 → ページ送り(マーカー記録) → 発表終了 → ソース化 → 自動リンク+ページ割当
```

## 6. 発表UIの詳細フロー

### 開始導線
- ソース一覧のPDF/PPTXソースカードの既存メニューに「発表を開始」を追加(縦にUIを肥大化させない)
- PPTXで変換済みPDFが無い場合は項目を無効化し、ツールチップで「PDFに書き出して取り込むと発表できます」と案内
- 押下すると確認なしで即開始: 既存の録音開始と同じ設定(マイク+システム音声)でセッション開始し、
  発表ビューへ切替。開始と同時にページ1のマーカーを自動記録

### 発表中の画面
- 中央: スライド(pdf.js、1ページフィット表示)。下部バーはページ位置(◀ N/M ▶)のみ
- 右: ライブ字幕サイドバー(話者名+時刻付き履歴、自動スクロール+遡り可)
- 左: ソース一覧は継続表示。録音コントロール(録音中表示・経過時間・ミュート・発表を終了)は
  既存録音機能と同じ左欄上部(SourcesPanel内RecordingControls)を流用
- ソースカードは既存の見た目のまま(アイコン追加なし)。発表資料の下に録音が子としてインデント表示
- チャットは非表示(録音中の既存挙動と同じ)

### ページ操作
- ◀▶ボタン、キーボード(←/→、Space=次へ)、マウスホイール(下=次ページ/上=前ページ、PowerPointと同じ感覚)
- ページ番号クリックで直接ジャンプ入力。サムネイル一覧はv1非対応
- 操作方法のヒントはUIに常時表示しない(必要ならツールチップ等の最小限に留める)
- ホイールの内部動作: スライドはフィット表示のためホイールをページ切替に使用。字幕サイドバーや
  ソース一覧の上では通常スクロール。誤切替防止に約150msのスロットリング(画面には表示しない実装仕様。
  300msは操作感が鈍いという既知フィードバックに従い150ms以下とする)

### ページマーカーの記録
- ページ変更のたびにフロントがマーカーAPIへ `{kind:"page", value:N}` をPOST。`at_ms` はサーバー側で
  録音タイムラインから算出(クライアントの時計に依存しない=字幕と同じ時刻基準)
- 送信失敗してもUIは続行(次のページ送りで回復)
- ページを戻った場合も普通にマーカーを記録=同一ページに複数の発言区間が付くことを許容

### 終了フロー
1. 左欄の「発表を終了」→ 確認ダイアログ(誤タップ防止)→ 録音停止
2. 既存の録音ソース化パイプラインがそのまま実行される(JobStatusBarに進行表示)
3. ソース化完了時に自動リンク(relation=presentation)+ページ割当
4. 録音タイトルの既定は「{資料名} 発表 YYYY-MM-DD」(既存のタイトル推論より発表文脈を優先)
5. 画面は通常のチャット画面に戻る

### 中断・異常系
- ブラウザリロード時: サーバー側の録音セッションは継続。ページ再訪時に「発表セッション進行中」を
  検出して発表ビューへ復帰(表示中ページはサーバーの最終マーカーから復元)
- 録音セッションが落ちた場合: 既存のクラッシュ検出(CrashDetectionModal)に委ねる

## 7. ナレッジ活用と検索・引用

方針: v1では親子リンクとページ紐付けを「表示とナビゲーションの強化」に使う。検索スコアリング
自体の変更は行わない(発表録音のチャンクは従来どおり通常のRAG検索対象として自然にヒットする)。

### 引用の見せ方
- 発表録音のチャンクが引用された場合: 引用一覧の表記に親リンク情報を含める
  (例:「{録音名} — p.N での発言」)。ソースビューアには「親: {資料名} の p.N で発言」と
  「該当スライド(p.N)を表示」導線を追加
- 「該当スライドを表示」でソースビューア内にpdf.jsで親資料の該当ページを描画(発表モードと同じ描画部品)
- スライド資料側のチャンクが引用された場合: ソースビューアに「このページでの発言 N件」を併記
  (`source_links` 経由の逆引き)、クリックで子録音の該当セグメントへ
- 音声の該当箇所再生は既存のAudioCitationPlayer/SharedAudioPlayerをそのまま使用

### スライド閲覧の強化
- スライドソースをソースビューアで開いたとき、ページごとに「このページでの発言」(子録音のセグメント)を
  折りたたみで表示し、該当箇所から音声再生できる
- 複数回の発表(同じ資料に子録音が複数)がある場合は録音ごとにグループ表示

### 手動リンクの操作
- ソースカードの既存メニューに「親ソースを設定…」「リンクを解除」を追加。設定は同一ノートブック内の
  ソースを選ぶだけの小さなダイアログ
- ソース一覧のツリー表示は1階層のインデントのみ(データ上は多段リンク可能だが、v1のUIは1階層表示)
- 手動リンク(relation=manual)にはページ紐付けはない(ソース単位の関係のみ)

## 8. エラー処理

| 状況 | 挙動 |
|---|---|
| PowerPoint無し環境でPPTXを取込 | テキスト取込は従来どおり成功(検索・チャットには使える)。「発表を開始」のみ無効化+PDF化ガイド |
| COM変換失敗(破損PPTX・ハング等) | 取込自体は継続(テキストのみ)。変換失敗を警告表示し、発表は不可。タイムアウト付きでPowerPointプロセスを確実に後始末 |
| recording extra未導入で発表開始 | 503+導入ヒントToast(既存録音と同じグレースフルデグレードのパターン) |
| 別の録音セッションが進行中 | 発表開始を拒否してToast表示(同時1セッションの既存制約に従う) |
| ページマーカーのPOST失敗 | UIは続行(ベストエフォート)。マーカー全滅でもソース化と親子リンクは成立し、ページ割当のみ欠落 |
| pdf.jsの描画失敗 | スライド領域にエラー表示。録音は継続し、左欄から通常どおり終了できる(録音データを失わない) |
| ブラウザリロード/タブ閉じ | サーバー側セッションは継続。再訪時に発表ビューへ復帰(最終マーカーのページを表示) |
| サーバークラッシュ | 既存のクラッシュ検出(CrashDetectionModal)と部分データ復旧に委ねる |

## 9. テスト & 検証ゲート

### テスト
- 単体: マーカー→ページ割当ロジックの境界(ページ戻り/スキップ/マーカー無し/最終ページ/
  マーカー時刻とセグメント境界の跨り)、`source_links` の自己リンク・重複・循環拒否
- 統合: マーカー記録API、`source_links` CRUD API、PPTX取込時のCOM変換(COMはモック、失敗系含む)、
  ソース化完了時の自動リンク+`chunks.page` 書込、PDF配信API
- フロント: 発表ビューのページ操作(ボタン/キーボード/ホイール+スロットリング)とマーカー送信、
  字幕サイドバー表示、親子ツリー表示

### 検証ゲート(必須)
- GUI変更のため、自動テストGREENだけではPASSにしない。Evaluatorによる実機スクリーンショット検証
  (発表開始→ページ送り→ライブ字幕→終了→ソース化→親子ツリー→引用から該当スライド表示の一連)を
  PASS条件に含める

## 10. 受入基準

- PDF/PPTXソースから「発表を開始」でき、スライドが見た目のまま中央に表示される
- ページ送りが◀▶ボタン・キーボード(←/→/Space)・マウスホイール(スライド領域上)のいずれでも操作できる(操作ヒントは常時表示しない)
- 発表中のページ送りがマーカー(kind=page, value, at_ms)として記録される
- 発表中、右サイドバーに話者名付きライブ字幕が履歴表示される
- 録音コントロール(録音中表示・ミュート・発表を終了)は既存録音機能と同じ左欄に表示される
- 発表終了後、録音が既存パイプラインでソース化され、発表資料の子として自動リンクされる(relation=presentation)
- 録音チャンクに「そのとき表示していた発表資料のページ番号」が割り当てられる
- 発表録音チャンクの引用から、紐付く親資料の該当スライドページを表示できる
- 任意のソースを手動で別ソースの子としてリンク/解除でき、ソース一覧が親子ツリーで表示される(カードの見た目は既存のまま)
- PowerPoint無し環境でPPTXの発表を試みると「PDFに書き出して取り込む」案内が表示される(機能全体は壊れない)
- GUI変更のため、自動テストGREENに加えてEvaluatorによる実機スクリーンショット検証をPASS条件に含める

## 11. リスク / 留意点

| リスク | 対策 |
|---|---|
| PowerPoint COM自動化は対話ユーザーセッションでの実行が前提(サービス起動やヘッドレス環境では失敗しうる) | 起動時にCOM利用可否を検出し、不可ならPDF化ガイドへフォールバック |
| `chunks.page` 流用により録音ソースの `page` の意味が「親発表資料のページ」になる(文脈依存) | specとコードコメントで意味を明記し、SourceViewer表示側で誤解のないラベルを付ける |
| ライブ字幕とページ操作の同時進行での時刻ずれ(マーカー `at_ms` と字幕タイムラインの基準差) | 既存のmic/system共有epoch(perf_counter基準)と同じ時刻基準をマーカーにも使用する |
