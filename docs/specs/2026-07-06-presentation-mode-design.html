Overview

スライド資料(PDF/PPTX)を見た目のまま表示しながら発表を録音し、発言をページ単位で資料に紐付けてナレッジを強化する機能。中央のチャット領域をスライド表示に置き換え、右サイドバーに話者名付きのライブ字幕を表示する。録音は既存の録音パイプライン(マイク+システム音声+話者分離)を再利用し、録音セッションには汎用タイムラインマーカー機構(案C)を追加してページ遷移を記録する。あわせて、ソース同士を親子リンクできる汎用基盤(source_links)を導入し、発表録音は発表資料の子として自動リンク、任意ソースの手動リンクも可能にする。※2026-07-06 ブレインストーミング完了、全セクション承認済み。

Goals

  • 発表資料(PDF/PPTX)をアプリ内で見た目のまま表示しながら録音できる(利用シーンは実際の発表・会議が主)
  • 発言(文字起こし)をページ単位で発表資料に紐付け、ナレッジの結合度を高める
  • 発表中に右サイドバーへ話者名付きライブ字幕を履歴表示し、ライブ感を提供する
  • ソース親子リンクの汎用基盤を導入する(発表モードによる自動リンク+任意ソースの手動リンクの両方をv1で提供)
  • PPTXはPowerPoint COMで取込時にPDF化して忠実に表示する。PowerPoint無し環境では『PDFに書き出して取込』をガイドするグレースフルデグレード
  • 既存資産(録音セッション/LiveCaption/話者分離/ソース化パイプライン/chunks.page列/RecordingControls)を最大限再利用し、UIの新規部品追加を最小に抑える

Non-Goals

  • PowerPointアニメーション・段階表示の再現(PDF化の時点で失われる)
  • レーザーポインタ・描画注釈・発表タイマー等のプレゼンター補助ツール
  • 発表モード中のRAGチャット並用(録音中と同様にチャットは非表示)
  • スライドサムネイル一覧からのページジャンプ(v1はページ番号入力のみ)
  • リンクを使った検索スコアリングの変更(v1はリンクを表示・ナビゲーション強化にのみ使用)
  • LibreOfficeによるPPTX変換フォールバック(v1はPowerPoint COMのみ、無い環境は手動PDF化ガイド)
  • 発表のライブ配信・外部共有機能

開始導線

  • ソース一覧のPDF/PPTXソースカードの既存メニューに「発表を開始」を追加(縦にUIを肥大化させず既存アフォーダンスを再利用)

  • 異常系は Watchdog で監視

※モックアップ: 配色・部品は実アプリのデザイントークン(app.css)と既存コンポーネントに準拠。録音コントロール(録音中表示・経過時間・ミュート・発表を終了)は既存録音機能と同じ左欄上部(RecordingControlsの位置)。ソースカードは既存の見た目のまま(アイコン追加なし)、発表資料の下に録音がインデントで子表示。操作ヒントは画面に常時表示しない。

  • ページ操作: ◀▶ボタン、キーボード(←/→、Space=次へ)、マウスホイール(下=次ページ/上=前ページ、PowerPointと同じ感覚)。ページ番号クリックで直接ジャンプ入力。サムネイル一覧はv1非対応
  • 操作方法のヒントはUIに常時表示しない(必要ならツールチップ等の最小限に留める)
  • ホイールの内部動作: スライドは1ページフィット表示のためホイールはページ切替に使用。字幕サイドバーやソース一覧の上では通常のスクロール動作。誤切替防止に約150msのスロットリング(300msは操作感が鈍い既知フィードバックに従う。この挙動は実装仕様であり、画面には表示しない)
  • スライド下部バーはページ位置(◀ N/M ▶)のみ。録音コントロール(録音中表示・経過時間・ミュート・発表を終了)は既存の録音機能と同じ左欄(SourcesPanel上部のRecordingControls)を流用
  • チャットは非表示(録音中の既存挙動と同じ)

ページマーカーの記録

  • ページ変更のたびにフロントがマーカーAPIへ {kind:"page", value:N} をPOST。at_msはサーバー側で録音タイムラインから算出(クライアントの時計に依存しない=字幕と同じ時刻基準)
  • 送信失敗してもUIは続行(次のページ送りで回復)
  • ページを戻った場合も普通にマーカーを記録=同一ページに複数の発言区間が付くことを許容

終了フロー

  1. 左欄の「発表を終了」→ 確認ダイアログ(誤タップ防止)→ 録音停止
  2. 既存の録音ソース化パイプラインがそのまま実行される(JobStatusBarに進行表示)
  3. ソース化完了時に自動リンク(relation=presentation)+ページ割当
  4. 録音タイトルの既定は「{資料名} 発表 YYYY-MM-DD」(既存のタイトル推論より発表文脈を優先)
  5. 画面は通常のチャット画面に戻る

中断・異常系

  • ブラウザリロード時: サーバー側の録音セッションは継続。ページ再訪時に「発表セッション進行中」を検出して発表ビューへ復帰(表示中ページはサーバーの最終マーカーから復元)
  • 録音セッションが落ちた場合: 既存のクラッシュ検出(CrashDetectionModal)に委ねる

ナレッジ活用と検索・引用

方針: v1では親子リンクとページ紐付けを「表示とナビゲーションの強化」に使う。検索スコアリング自体の変更は行わない(発表録音のチャンクは従来どおり通常のRAG検索対象として自然にヒットする)。

  • 発表録音のチャンクが引用された場合: 引用一覧の表記に親リンク情報を含める(例:「{録音名} — p.N での発言」)。ソースビューアには「親: {資料名} の p.N で発言」と「該当スライド(p.N)を表示」導線を追加

  • スライド資料側のチャンクが引用された場合: ソースビューアに「このページでの発言 N件」を併記(source_links経由の逆引き)、クリックで子録音の該当セグメントへ
  • 音声の該当箇所再生は既存のAudioCitationPlayer/SharedAudioPlayerをそのまま使用

スライド閲覧の強化

  • スライドソースをソースビューアで開いたとき、ページごとに「このページでの発言」(子録音のセグメント)を折りたたみで表示し、該当箇所から音声再生できる
  • 複数回の発表(同じ資料に子録音が複数)がある場合は録音ごとにグループ表示

手動リンクの操作

  • ソースカードの既存メニューに「親ソースを設定…」「リンクを解除」を追加。設定時は同一ノートブック内のソースを選ぶだけの小さなダイアログ
  • ソース一覧のツリー表示は1階層のインデントのみ(データ上は多段リンク可能だが、v1のUIは1階層表示)。カードの見た目自体は既存のまま
  • 手動リンク(relation=manual)にはページ紐付けはない(ソース単位の関係のみ)

エラー処理

状況挙動
PowerPoint無し環境でPPTXを取込テキスト取込は従来どおり成功(検索・チャットには使える)。「発表を開始」のみ無効化+PDF化ガイド
COM変換失敗(破損PPTX・PowerPointハング等)取込自体は継続(テキストのみ)。変換失敗を警告表示し、発表は不可。タイムアウト付きでPowerPointプロセスを確実に後始末
recording extra未導入で発表開始503+導入ヒントToast(既存録音と同じグレースフルデグレードのパターン)
別の録音セッションが進行中発表開始を拒否してToast表示(同時1セッションの既存制約に従う)
ページマーカーのPOST失敗UIは続行(ベストエフォート)。マーカーが全滅してもソース化と親子リンクは成立し、ページ割当のみ欠落
pdf.jsの描画失敗スライド領域にエラー表示。録音は継続し、左欄から通常どおり終了できる(録音データを失わない)
ブラウザリロード/タブ閉じサーバー側セッションは継続。再訪時に発表ビューへ復帰(最終マーカーのページを表示)
サーバークラッシュ既存のクラッシュ検出(CrashDetectionModal)と部分データ復旧に委ねる

テストと検証ゲート

  • 単体: マーカー→ページ割当ロジックの境界(ページ戻り/スキップ/マーカー無し/最終ページ/マーカー時刻とセグメント境界の跨り)、source_linksの自己リンク・重複・循環拒否
  • 統合: マーカー記録API、source_links CRUD API、PPTX取込時のCOM変換(COMはモック、変換失敗系含む)、ソース化完了時の自動リンク+chunks.page書込、PDF配信API
  • フロント: 発表ビューのページ操作(ボタン/キーボード/ホイール+スロットリング)とマーカー送信、字幕サイドバー表示、親子ツリー表示
  • Evaluator実機検証(必須ゲート): 発表開始→ページ送り→ライブ字幕→終了→ソース化→親子ツリー→引用から該当スライド表示、の一連をスクリーンショット付きで検証。GUI変更のため自動テストGREENのみではPASSにしない

Acceptance criteria

  • PDF/PPTXソースから『発表を開始』でき、スライドが見た目のまま中央に表示される
  • ページ送りが◀▶ボタン・キーボード(←/→/Space)・マウスホイール(スライド領域上)のいずれでも操作できる(操作ヒントは常時表示しない)
  • 発表中のページ送りがマーカー(kind=page, value, at_ms)として記録される
  • 発表中、右サイドバーに話者名付きライブ字幕が履歴表示される
  • 録音コントロール(録音中表示・ミュート・発表を終了)は既存録音機能と同じ左欄に表示される
  • 発表終了後、録音が既存パイプラインでソース化され、発表資料の子として自動リンクされる(relation=presentation)
  • 録音チャンクに『そのとき表示していた発表資料のページ番号』が割り当てられる
  • 発表録音チャンクの引用から、紐付く親資料の該当スライドページを表示できる
  • 任意のソースを手動で別ソースの子としてリンク/解除でき、ソース一覧が親子ツリーで表示される(カードの見た目は既存のまま)
  • PowerPoint無し環境でPPTXの発表を試みると、『PDFに書き出して取り込む』案内が表示される(機能全体は壊れない)
  • GUI変更のため、自動テストGREENに加えてEvaluatorによる実機スクリーンショット検証をPASS条件に含める

Risks

RiskMitigation
PowerPoint COM自動化は対話ユーザーセッションでの実行が前提(サービス起動やヘッドレス環境では失敗しうる)起動時にCOM利用可否を検出し、不可ならPDF化ガイドへフォールバック(グレースフルデグレード)
chunks.page列の流用により、録音ソースのpageの意味が『親発表資料のページ』になる(文脈依存)specとコードコメントで意味を明記し、SourceViewer表示側で誤解のないラベルを付ける
ライブ字幕とページ操作の同時進行での時刻ずれ(マーカーat_msと字幕タイムラインの基準差)既存のmic/system共有epoch(perf_counter基準)と同じ時刻基準をマーカーにも使用する
